# Ahl El Kheir Internationalization (AR / EN)

Arabic is the default language and English is the alternate language.

## Architecture

The project is moving to **stable key-based i18n**. New UI code must never use an Arabic sentence as its translation identifier.

- `config/lang.php` resolves the active language and provides `t()` / `ak_t()`.
- `lang/ar.php` is the authoritative Arabic key catalog.
- `lang/catalog_en.php` is the authoritative English key catalog.
- `lang/en.php` is a temporary legacy compatibility catalog for pages that have not yet been migrated.
- `assets/js/language.js` supports client-side dynamic UI and receives the active catalog through the footer.
- `tools/i18n_audit.php` is the developer audit for catalog parity, translation-key usage, and hard-coded Arabic literals.

## New code

PHP:

```php
echo t('families.add');
echo t('families.total', ['count' => $total]);
```

JavaScript:

```javascript
AKLang.t('messages.send');
```

Translation keys are stable identifiers such as `families.add`, `messages.send`, and `common.save`.

## Dynamic values

Use placeholders instead of translating rendered sentences:

```php
echo t('families.total', ['count' => $total]);
```

Catalog entry:

```text
families.total = Total Families: :count
```

The value is inserted after the translation is selected.

## Critical data rule

**Never translate database data.** Names, addresses, notes, phone numbers, case information, sponsor information, document names, and other stored business data must remain exactly as stored. Only application UI belongs in translation catalogs.

## Legacy migration

Existing Arabic=>English entries remain temporarily available through `lang/en.php` so the application does not break while pages are migrated. They are a compatibility bridge, not the architecture for new development.

No new entries should be added to the legacy catalog. When an existing page is migrated, replace its Arabic UI literal with a stable key and add the key to both authoritative catalogs.

## Language switching

The selected language is stored in the `ak_lang` cookie. Language links are normalized so repeated switches do not accumulate duplicate `lang` query parameters. English uses LTR Bootstrap; Arabic uses RTL Bootstrap.

## Audit

From the project root run:

```text
php tools/i18n_audit.php
```

The audit verifies that Arabic and English key catalogs contain the same keys and reports unknown translation-key usages and Arabic source literals for review.

## Development rule

Do not create page-specific translation dictionaries, replacement scripts, or runtime harvesting. Every new UI term must be introduced as a stable key in both authoritative catalogs and used through the central helpers.
