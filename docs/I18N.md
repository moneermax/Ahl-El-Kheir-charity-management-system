# Ahl El Kheir Internationalization (AR / EN)

The application uses Arabic as the default language and English as the alternate language.

## Architecture

- `config/lang.php` is the server-side i18n bootstrap.
- `lang/common.php` contains shared UI translations.
- `lang/en.php` contains the existing application dictionary and remains backward compatible.
- `assets/js/language.js` handles UI created after the initial page load, including AJAX/modal content.
- `t('...')` / `ak_t('...')` are the preferred PHP helpers for new UI text.
- `AKLang.t('...')` is the preferred JavaScript helper for new dynamic UI text.

## Important rule

**Never translate database data.** Names, addresses, notes, phone numbers, case information, sponsor information, and other stored business data must remain exactly as stored. Only UI strings belong in the dictionaries.

## Backward compatibility

Existing pages do not need to be rewritten in one large migration. The server translation layer safely translates known UI strings already present in the dictionary, while new code should use explicit translation calls. This lets the codebase migrate incrementally without another fragile global HTML replacement system.

## Dynamic UI

JavaScript-generated text should use `AKLang.t('Arabic UI text')`. Prefer stable translation keys for newly migrated modules.

The runtime also observes newly inserted DOM nodes so translated modal, AJAX, and dynamically generated UI text is handled consistently.

## Language switching

The selected language is stored in the `ak_lang` cookie. The language link is normalized client-side so repeated switches do not accumulate duplicate `lang` query parameters.

English pages also switch Bootstrap from the RTL stylesheet to the normal LTR stylesheet.

## Development rule

Do not add another page-specific translation mechanism. Do not add page-specific replacement scripts. Add UI translations to the central dictionary and use the central helpers/runtime.
